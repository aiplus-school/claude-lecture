# 台本 — Higgsfield MCP　Claude Codeから動画を生成しよう

## [P1] カバー — Higgsfield MCP　Claude Codeから動画を生成しよう

今回は、Higgsfield（ヒッグスフィールド）を Claude Code につないで、**会話だけで動画を作る**方法を学びます。

Higgsfield は、AIで動画を作るサービスです。本来はブラウザの画面で使うもので、基礎講座でも動画生成のツールとして紹介しました。今回は、それを Claude Code から直接呼び出せるようにします。

作るのは、**5枚の画像を順につないだ、ひと続きの動画**です。1枚から1本を作って終わりではなく、**場面が移り変わっていく動画**を、会話だけで組み立てていきます。

---

## [P2] Higgsfield MCP とは — Claude Code を Higgsfield につなぐ

MCP、「Model Context Protocol（モデル・コンテキスト・プロトコル）」は、AIが外部のツールと連携するための共通規格です。

なぜこれが必要なのか。**Claude は、文章やコードは書けますが、動画そのものを作ることはできません。** 動画を作る機能を持っていないからです。どんなに良い演出を考えてくれても、それを形にするには、結局こちらが別のサービスの画面を開いて、考えてもらった内容を打ち込み直すことになります。

そこで使うのが、Higgsfield が用意している MCP です。これでつなぐと、**Claude が考えた内容が、そのまま Higgsfield に渡って動画になります。** 打ち込み直す手間がなくなり、出てきた動画を見て「ここを直したい」と伝えれば、そのまま作り直してもらえます。

---

## [P3] Remotion の回との違い — コードで組み立てるか、生成モデルに作らせるか

セクション8では、前に **Remotion（リモーション）** も扱いました。あちらも Claude Code で動画を作る話だったので、**何が違うのか**を先に整理しておきます。

**Remotion は、コードで動画を組み立てる道具**でした。「1コマ目はここに文字、10コマ目は少し右へ」というふうに、**計算で動かします。** 書いたとおりに動くので、**何度作っても同じものが出てきます。**

**今回の Higgsfield は、動画を作るAIのモデルに、映像そのものを作ってもらいます。** こちらが渡すのは、画像と言葉です。**一コマずつをこちらが決めるのではなく、モデルが映像を作ります。** ですから、同じことを頼んでも、**毎回少しずつ違うものが出てきます。**

もうひとつ、**動画がどこで作られるか**も違います。**Remotion は、自分のパソコンの中で計算して動画を書き出していました。** いっぽう **Higgsfield は、Veo（ヴィオ）や Seedance（シーダンス）といった動画生成モデルを呼び出して作ります。** これらは Higgsfield が開発したモデルではなく、**他社が提供しているAIのモデル**です。

> （※テロップ／概要欄）Veo・Seedance ＝ 動画を生成するAIのモデルの名前。Higgsfield では、こうしたモデルを30種類以上から選んで使えます。

ここが、**費用のかかり方**につながります。**本来、こうしたモデルを使うには、モデルごとに契約して「APIキー」という鍵を受け取る必要があります。** Higgsfield は、そのやりとりをまとめて引き受けてくれているので、**私たちがAPIキーを用意する必要はありません。** そのかわり、**生成のたびに Higgsfield のクレジットが減ります。**

> （※テロップ／概要欄）APIキー ＝ サービス同士をつなぐときに使う、パスワードのような文字列。**今回はご自分で用意する必要はありません。**／クレジット ＝ 生成のたびに減る、プランごとの残数。

この違いは、そのまま**作れるもの・直し方・素材の扱いの違い**になります。**並べた一覧をスライドに出しておくので、そのうち3つだけ、口で補足させてください。**

（[P3] のスライドに、下の一覧を表示しておく。**読み上げはしない**）

| | Remotion | Higgsfield |
|---|---|---|
| 作り方 | コードで組み立てる | AIのモデルに作らせる |
| 得意なもの | 文字・図形・データを使った動画 | 実写のような映像・人が自然に動く映像 |
| 同じものを作り直せるか | 何度でも同じ | 毎回変わる |
| 直したいとき | その部分だけ直せる | その区間を作り直す |
| 素材の画像 | 自分のパソコンから出ない | Higgsfield に送って、そこで作ってもらう |
| 費用のかかり方 | 作るたびの費用はかからない | 作るたびにクレジットが減る |

**1つ目は、得意なものです。** **人が自然に動く映像のように、一コマずつ組み立てるのが難しいものは、Higgsfield の側が得意です。** Remotion の公式ドキュメントにも、**写実的な映像づくりは Remotion の範囲外**だと書かれています。**人物の画像を1枚登録して、同じ人を別の場面に登場させる**こともできます。**これは今回、実際に使います。**

**2つ目は、直したいときです。** 「文字の位置を少しずらしたい」「秒数だけ変えたい」。**こうした直しは、Remotion ならその部分だけ書き換えれば済みます。** Higgsfield では、もう一度作り直すことになります。そのとき、**直したいところ以外、背景や動きまで変わってしまうことがあります。** 作り直すのも生成なので、**書いたとおりそのまま、とはならないことがあります。**

**3つ目は、素材の画像の扱いです。** ここは、仕事で使う場合に関わってきます。**Remotion は自分のパソコンの中で動画を書き出すので、素材が手元から出ません。** いっぽう **Higgsfield は、素材にする画像を Higgsfield 側に送って、そこで動画を作ってもらう仕組み**です。**社外に出せない写真や、公開前の商品の画像を使うときは、送っていいものかどうかを先に確認してください。**

そのうえで、**この2つは組み合わせても使えます。** 今回のように Higgsfield で映像を作って、そこに Remotion でテロップを乗せる、という進め方もできます。

## [P4] なぜブラウザで使わず、Claude Code につなぐのか

Higgsfield は、ブラウザの画面だけでも使えます。**1本だけ作るなら、ブラウザで十分です。** そのうえで Claude Code につなぐ理由は、2つあります。

**1つ目。同じ作業を繰り返すところを、まとめて頼めること。** 今回作るのは、**4つの区間をつないだ1本の動画**です。ブラウザでこれをやると、**区間ごとに画像を2枚選んで、指示を書いて、出来上がるのを待つ**——これを4回繰り返し、そのあと**4本を1本につなぐ作業**が別に必要になります。Claude Code なら、この一連を**会話の中でまとめて頼めます。**

**2つ目。他の作業と地続きになること。** 作った動画は、**手元のフォルダにファイルとして残ります。** ですから、そのまま次の作業に使えます。**どう使えるかは、動画を作り終えたあとに説明します。**

つまり今回の役割分担は、**Claude が「どんな動画にするかを一緒に考えて、手順をまとめて進める役」、Higgsfield が「実際に動画を作る役」**です。この形で進めていきます。

## [P5] 始める前に — 2つだけ確認

実演に入る前に、前提を2つだけお伝えします。

**1つ目。動画の生成は、有料プランが前提です。しかも、いちばん安いプランでは足りません。** 無料で使える範囲では、**今回使う動画のモデルがそもそも対象外**です。そして**いちばん安い有料プランも、使えるモデルが限定されていて対象外**なんです。今回使う「画像と画像の間をつなぐ」機能も、そこには入っていません。

**選ぶときの目印は、料金ページに「すべてのモデルと機能が使える」と書かれているかどうかです。** プラン名は、開くタイミングによって **Plus** と表示されることも、**Pro** と表示されることもあります。**迷ったら、このどちらかを選んでください。** 金額も変わることがあるので、**最新の情報は概要欄のリンクから公式サイトで確認**してください。

**2つ目。動画のもとにする画像は、あらかじめ用意しておきます。** 今回は、こちらで事前に用意した5枚を使います。**同じ画像は概要欄にリンクを置いておく**ので、ダウンロードしていただければ、この先はまったく同じ手順で試せます。

## [P6] 素材の5枚と、つなぎ方

（画面収録からスライドに切り替えて説明する）

今回の素材は、**場面の始まりとなる5枚の画像**です。プロジェクトの `素材画像/` フォルダに、順番が分かる名前で入れてあります。

> `素材画像/01_看板.png` → `02_カウンター.png` → `03_抽出.png` → `04_ドリンク.png` → `05_客席.png`

**なぜ画像を先に用意するのか。** 「何が写っているか」を画像のほうで決めてしまえば、**こちらは「その間をどう動くか」を伝えることに集中できる**からです。

そのうえで、今回使うのが **Higgsfield の「画像と画像の間をつなぐ」機能**です。**始まりの画像と終わりの画像を渡すと、その間の動きを作ってくれます。**

ここが大事なところなので、図で確認します。この機能は**2枚1組**です。ですから5枚をつなぐには、**となり合う2枚ずつ、4つの区間**を作ることになります。

> **区間1**：01_看板 → 02_カウンター
> **区間2**：02_カウンター → 03_抽出
> **区間3**：03_抽出 → 04_ドリンク
> **区間4**：04_ドリンク → 05_客席
>
> **1区間5秒 × 4区間 ＝ 合計20秒**

**なぜ各区間を5秒にするのか。** 短くすると早く仕上がり、直したいときにやり直しやすいからです。**5秒×4区間で20秒**、というのはあとで確認するときにも使うので、覚えておいてください。

そして最後に、**この4本を1本につないでもらいます。** ここまで全部、会話で頼みます。

## [P7] 動画の指示は「5つの要素」で組み立てる

（続けてスライドで説明する）

区間の中身をどう伝えるか、という話です。静止画なら「何が写っているか」を書けば伝わりますが、動画は**「どう動くか」まで**書かないと伝わりません。

うまくいく指示は、だいたいこの5つの要素でできています。

> **① 被写体**（何を）／**② 動き**（何がどう動くか）／**③ カメラワーク**（寄る・引く・横に動く）／**④ 雰囲気**（明るさ・時間帯・トーン）／**⑤ 尺とモデル**（何秒か・どの設定で作るか）

今回は、このうち**①被写体と④雰囲気は、渡す2枚の画像がほぼ決めてくれます。** ですから、こちらが言葉で埋めるのは、**②動きと③カメラワーク**が中心になります。

たとえば「この2枚をつないで」とだけ伝えると、AIは間をどう動かせばいいのか判断できません。結果、2枚が入れ替わるだけの、ほとんど止まったような画になりがちです。

一方、**「カウンターに向かってカメラがゆっくり前に進みながら、湯気が立ちのぼる」**と伝えると、動きもカメラも決まります。**この差で、仕上がりが変わってくることがあります。**

**⑤の尺とモデルは、各区間5秒・720p（ナナヒャクニジュウピー）という軽い解像度で、モデルは Kling 3.0（クリング）を指定します。** さきほどお話しした「短いほど直しやすい」に加えて、**[P3]でお話ししたとおり、作るたびにクレジットが減ります。** まずは軽い解像度で試してみるほうが、無駄が少なくなります。**モデルを指定しないと、Claude が別のモデルを選ぶことがあります。同じ5秒でも、モデルによって減るクレジットは変わります。**

> （※テロップ／概要欄）720p ＝ 動画の解像度のひとつ。数字が大きいほど画がきめ細かくなり、そのぶんクレジットを多く使います。／**モデルの名前は入れ替わることがあります。** 指定するときは、公式サイトでいま使えるものを確認してください。

とはいえ、4区間ぶんの指示を毎回自分で書き切るのは大変です。**そこで Claude に相談します。**

### 作る前に、区間ごとの構成を相談する

**使うのは、プロンプト集のP2です。** 5枚の画像を4区間でつなぎたいこと、各区間5秒であることを伝えたうえで、**「まだ生成しないでください」と釘を刺して**、**区間ごとに②動きと③カメラワークをどうするか**の案を先に出してもらう内容です。あわせて、**残りのクレジットでこの条件が作れるか**も見てもらいます。

**なぜ、いきなり作らせないのか。** 動画の生成は、投げてから出来上がるまで時間がかかります。**しかも今回は4本分です。** イメージと違うものが4本出てきてから作り直すより、**文字のやりとりの段階で方向性を合わせておくほうが、結果的に早くなります。**

**クレジットを一緒に確認してもらっているのにも理由があります。** つないでいると、**Claude Code から残高を読めます。** そのため、自分で残高を見て割り算しなくても、**足りるかどうかの判断ごと任せられます。** 足りなければ、区間の数や1区間の秒数をどう配分するかの案も返ってきます。

（P2を貼り付けて実行。返ってきた区間ごとの案を画面に映し、区間1から区間4まで並んでいるところをスクロールして見せる。そのあと、クレジットの確認が書かれているところまでスクロールする）

区間ごとに、どこからどこへ、何がどう動くのかが言葉になっています。**場面の流れとして、つながっているかどうか**をここで見ます。残りのクレジットでも足りるとのことなので、このまま生成に進みます。

**Claude Code のプランモードでも、同じことができます。** 実行する前に「こう作ります」という計画を出して、こちらの承認を待ってくれる機能です。

### 4つの区間をまとめて生成する

**ここで使うのは、プロンプト集のP3です。** さきほどの案でいきましょう、と伝えて、**4区間を順番に、各5秒・720pで**作ってもらいます。あわせて、できた動画をプロジェクトの `videos/` フォルダに保存するよう指定しています。**あとで4本を1本につなぐので、置き場所をこちらで決めておきます。**

（P3を貼り付けて実行。4区間が順番に生成されていく様子を見せる）

いま、区間1から順に作ってくれています。**ブラウザだと、ここで画像を2枚選んで、指示を書いて、待って——を4回繰り返すことになります。** その繰り返しをまとめて任せているところです。

動画の生成は「投げて、待つ」仕組みなので、すぐには返ってきません。**できあがると、画面上で動画も確認できます。** 保存先も一緒に返ってきます。

（4本の生成が終わり、保存先が表示されるのを確認する。待ち時間が長いときは編集でカットする）

### 生成された4本を、ここで一度見ておく

つなぐ前に、**4本をこの段階で見ておきます。**

**つないでしまうと、どこを直せばいいのか言いにくくなります。** 20秒のうちのどこか、という探し方になるためです。**区間ごとに見ておけば、直す場所を番号でそのまま伝えられます。**

ここで見るのは1点だけです。**頼んだ②動きと③カメラワークが、入っているかどうか。**

**①被写体と④雰囲気は、渡した画像がほぼ決めています。** ですから確かめる意味があるのは、**言葉で足した部分**です。「湯気を強めに」と頼んだ区間なら湯気が動いているか、「ゆっくり前に進む」と頼んだ区間ならカメラが進んでいるか。**自分が書いた言葉と、画を見比べます。**

### 気になる区間だけ、会話のまま直す

いま見た中で、**区間1に気になるところがありました。**

**カメラが前に進んでいるのに、コーヒーを作る台のほうまで一緒に後ろへ下がっています。** 店の中にある台が動くことはないので、これはおかしな動きです。**カメラが近づいたのなら、台は大きく見えるはずです。**

**こういうときも、入力欄に一から書き直す必要はありません。使うのは、プロンプト集のP4です。** **どの区間か**と、**どんな画にしたいか**を伝えると、**いまのやりとりを土台に、その区間だけ**作り直してくれます。

（P4に書き足した内容を画面に映してから、貼り付けて実行する）

今回は、**お客さんが歩いて店に入っていく、一人称視点**にしました。看板の横から歩き出して戸口をくぐり、中に入ったらカウンターに視線が落ち着く——という流れです。そのうえで、**「置いてあるものはその場にあり、近づくぶんだけ大きくなる」**と書き添えています。**さっき気になった動きは、この一文で直しています。**

**何がおかしいかではなく、どうなってほしいかを書きます。** 「台が下がっていておかしい」と伝えるより、**こう見えてほしいという形**で書くほうが、動きが決まります。

**カメラの動かし方ごと書き直しているのは、おかしな動きがカメラの進み方から出ているためです。** 気になったところだけをつつくより、**どう見えてほしいかを先に決めてしまうほうが早く済みます。**

（区間1だけが作り直される様子を見せる）

**どの区間かは、番号で伝えてください。** 言わないと、4本すべて作り直しになることがあります。**作り直しも生成なので、そのぶんクレジットを使うことになるので、気をつけましょう。**

（作り直した区間1を再生する）

**見るのは2つです。歩いて入っていく形になっているか。そして、さっき気になった台の動きが変わったかどうか。** カウンターやマシンがその場にとどまって、**近づくぶんだけ大きくなっていれば、狙いどおりです。**

### 場面に人を出す

ここまでは、用意した素材の画像だけで作ってきました。**そこに人を出すこともできます。**

ただ、**そのまま「バリスタを出して」と頼むと、生成のたびに顔や服装が変わります。** 区間をまたいで同じ人に出てもらうことができません。そこで、**出したい人の画像を1枚、先に登録しておきます。**

**使うのは、プロンプト集のP5です。** 人物の画像を登録して、その人がドリッパーに湯を注ぐ形で区間2を作り直してもらう内容です。**始まりと終わりの画像はそのままなので、構図は変えずに人だけを足します。**

（人物画像を1枚映してから、P5を貼り付けて実行。登録が終わり、区間2が作り直されるまでを見せる）

**生成の指示そのものは、さきほどと同じです。** ここで新しいのは**登録の部分**で、これは待ち時間なしで終わります。同じ人の写真を何枚も用意したり、学習が終わるのを待ったりはしません。

**できたものを見ます。ここで見るのは2つです。**

**1つ目、登録した画像と同じ人になっているか。**

（人物画像と、できた動画を並べて映す。服装と髪型を見比べる）

**2つ目、この人がしたことと、画面で起きていることがつながっているか。** 湯を注ぐと、その真下の器にコーヒーが落ちはじめる——**注ぐ動作と、コーヒーがたまることが、ひと続きに見えていれば狙いどおりです。**

（区間2を最後まで再生し、湯を注ぐところから、真下の器にコーヒーが落ちてたまるまでを見せる）

**動かすものは、始まりの画像に写っているものから選びます。** 終わりの画像にある器は、始まりの画像にもすでに並んでいます。そこへ**新しい物を持ってこさせると、その物が1個増えるだけ**になり、場面とつながりません。**すでにあるものを使って何をするか**——ここでは「ケトルで湯を注ぐ」——を書くと、**その動作が、コーヒーが入る原因になります。**

**この2つは、この作り方でしか出てこない見どころです。** 人が出てこない区間では、確かめようがありません。

これで、**素材の画像だけで作る形**と、**そこに人を出す形**の2つができました。**どちらが良いというものではなく、作りたいものによって選びます。** 風景だけを見せたいなら前者、お店や商品を人と一緒に見せたいなら後者です。**今回は、人を出す方で先に進めます。**

### 4本を1本につなぐ

では、4本を1本の動画にまとめます。**ここも会話で頼みます。**

**使うのは、プロンプト集のP6です。** `videos/` にある動画を**区間の順番どおりにつないで**、1本の動画として保存してもらう内容です。**区間2は2本あるので、どちらを使うかを書き添えています。** あわせて、**つなぎ目を0.5秒ずつ重ねる**ようにも頼んでいます。

**重ねるのは、区間が1本ずつ別々に作られているからです。** どの区間も**止まった画で終わり、止まった画から始まります。** そのままつなぐと、変わり目で**一度止まって見えます。** 少し重ねておくと、そこが目立ちません。

（P6を貼り付けて実行。つないだ動画が保存されるまでを見せる）

**つなぐ作業そのものは Higgsfield ではなく、Claude Code が手元でやってくれます。** 動画をつなぐ道具をこちらで探して使い方を調べる、という手間がここで消えています。

> **（※概要欄に条件込みで記載）** 動画をつなぐには、パソコンに動画編集用の道具（ffmpeg）が必要です。入っていない場合は Claude Code が入れ方を案内してくれますが、**パソコンへのインストールの許可を求められる場面があります。** 手順は概要欄に載せておきます。

### できた動画を確かめる

AIは「できました」と言っていますが、**ここで終わりにしません。** 指示した内容がそのとおり入っているかは、自分の目で確かめます。**動画は、それらしく出来ていても、頼んだ動きになっていないことがあります。**

（`videos/` フォルダを開く → つないだ動画を動画プレイヤーで再生して見せる。**音を出して再生する**）

見るところは4つです。

**1つ目、場面の数と順番。** 用意した5枚の場面が、**看板 → カウンター → 抽出 → ドリンク → 客席**の順に出てくるかを**数えながら**見ます。順番が入れ替わっていないかも、ここで分かります。

**2つ目、長さ。** 5秒の区間が4つで20秒、そこから**つなぎ目で重ねたぶんが引かれます。** つなぎ目は3つで0.5秒ずつなので、**18秒台**になっているはずです。プレイヤーに出ている再生時間と見比べてください。**5秒近く足りなければ、どこかの区間が抜けています。**

**3つ目、つなぎ目。** 区間と区間の変わり目で、画がガクッと飛んでいないか。**これは、1本につないで初めて見えるところです。** さきほど区間ごとに見たときには分からなかった部分なので、ここで確かめます。

**4つ目、音。** **音は、こちらが頼まなくても生成に付いてきます。** ここでは、**4つの区間それぞれに音が入っているか**と、**つなぎ目で音が不自然に切り替わらないか**を聴きます。**区間ごとに別々に作っているので、音も区間ごとに別々に付きます。** 変わり目で音がぶつっと切れることがあるので、そこは耳で拾えます。

ここでイメージと違っても、やることは変わりません。**気になったところを日本語で伝えて、その区間をP4で作り直してもらいます。** **一度で仕上げようとせず、確かめて直す、を何回か繰り返すつもりで進めてください。**

なお、生成がうまくいかないときや、いつまでも終わらないときのために、**プロンプト集のP8**を用意しています。症状を伝えると、原因の見立てと直し方を教えてくれます。

## [P8] 作った動画を、次の作業につなげる — 3つの例

（画面収録からスライドに切り替えて説明する）

動画が1本できました。**そしてこの動画は、いまお使いのパソコンの、自分で決めたフォルダに入っています。** [P4]でお話しした「他の作業と地続きになる」というのは、このことです。

そこから先の使い道を、3つ挙げておきます。**どれも、今回と同じように会話で頼めます。**

**1つ目、作っているものに差し込む。** Webページや資料に、できた動画を組み込む使い方です。**ファイルが手元の決まった場所にあるので、そのまま指定できます。** ブラウザで作った場合は、ダウンロードして、フォルダに移して、読み込み先を書いて……という往復が要ります。そこが要らなくなります。

**2つ目、素材だけ差し替えて、もう1本作る。** 区間ごとの指示は、**会話の中に残っています。** ですから「同じ組み立てのまま、別の商品の画像5枚で作って」と頼めます。**1本目で時間をかけて練った指示を、2本目からは使い回せる**ということです。

**3つ目、できた動画を手元で加工する。** 別のサイズで書き出したい、一部だけ切り出したい、といったときです。**さきほど4本を1本につないだのと同じで、パソコンの中にある道具を Claude Code が使ってくれます。**

> 1つ目を試すためのプロンプトを、**プロンプト集のP7**に入れてあります。動画では実演していませんので、興味のある方はそちらをお使いください。

## [P9] クロージング — 考える Claude と、作る Higgsfield

今回は、Higgsfield を Claude Code に MCP でつないで、**5枚の画像を4つの区間でつなぎ、手直しをして、1本の動画にする**——ここまでを、ひと続きで見てきました。

今回追加で覚えて帰っていただきたいのは、**Claude Code に頼めば、Higgsfield の動画づくりを会話だけで進められる**ということです。ブラウザの画面を開いて、区間ごとに指示を打ち込んで、出てきたものをダウンロードして、つないで……という作業が、Claude との会話の中で完結しました。作る前に相談したり、気になる区間だけ直したりできたのも、この形にしたからです。

役割分担は、はじめにお話ししたとおり、**Claude が「どんな動画にするかを一緒に考えて、手順をまとめて進める役」、Higgsfield が「実際に動画を作る役」**です。動画づくりで手間がかかるのは、生成そのものよりも**「どう指示すればいいか」と「同じ作業の繰り返し」**だったりします。**そこを任せられるところが、ブラウザで単体で使うのとの違いです。**

## [P10] 最後に — 自分で試すときの注意点

自分で試すときの注意点を、いくつかお伝えします。

**指示は5つの要素で組み立てること。** 今回のように画像を2枚渡す場合は、**「動き」と「カメラワーク」**の2つが中心になります。5要素の表は概要欄にも載せてあります。

**作る前に、案を出してもらうこと。** 「まだ作らないで、まず案を見せて」と一言添えるだけで、やり直しが減ります。**とくに今回のように何本かまとめて作るときほど効きます。** プランモードを使うのも同じ狙いです。

**枚数・区間の数・秒数は、自分で指定すること。** 「いい感じにお願い」と任せきりにすると、**思っていたより本数が増えて、そのぶんクレジットを使ってしまう**ことがあります。まずは**今回のように区間を少なく、秒数も短く**して、通してみてください。慣れてきたら枚数を増やせます。

**仕事で使う場合は、権利のまわりを確認すること。** 生成したものをどこまで使えるかは、プランと利用条件によります。公式のリンクを概要欄に置いておきます。

そして、**一発で思いどおりにならないこともあります。** 今回お見せしたとおり、**まず軽く作って、確かめて、気になるところだけ直していく。** このやり方が結局は早いです。

まずは、みなさんの手元にある写真を2枚選んで、「この2枚の間をつなぐ動画を作るとしたら？」と Claude に相談するところから始めてみてはいかがでしょうか。
